# Decisions

Dated log of design decisions. Newest at the bottom. Each line: the decision, then why.

## 2026-11-11

| # | Decision | Why |
|---|---|---|
| 1 | Goal is learning first, but keep the design able to become a reliable tool. | Multi-agent roles are kept for learning value; typed interfaces let agents be swapped for code/templates later. |
| 2 | Agents: PM, Architect, Backend Eng, Frontend Eng, Tester (replacing DB Engineer + Developer). | DB/Developer were tightly coupled and sequential; backend/frontend split cleanly at the HTTP API and can run in parallel. |
| 3 | The Contract is a Pydantic model. | Same tooling as every other model; validated by code. |
| 4 | Request/response schemas are generated by code from the Contract. | Neither engineer can drift from the agreed shapes. |
| 5 | No human approval before the parallel step. | Keep runs automatic; validation by code catches structural errors. |
| 6 | If one branch fails, only that branch re-runs. | Don't redo work that passed. |
| 7 | Orchestrator uses asyncio; blocking CrewAI calls via `asyncio.to_thread`; `gather(..., return_exceptions=True)`. | Fits FastAPI; cancellation works for stop; `TaskGroup` would cancel sibling branches on failure. |
| 8 | The Architect writes all endpoints (no code-generated CRUD). | User choice; covered by stricter validator rules (path/status conventions, feature coverage). |
| 9 | One-to-many relations only. | Covers most simple apps; less generator and test work. |
| 10 | List endpoints return plain arrays, no pagination. | Simplest v1. |
| 11 | Generated code runs in a fresh container per check, from one prebuilt base image. | Clean state each round; fast because the fixed stack is preinstalled. |
| 12 | No packages beyond the base image. | Keeps the image valid; no install at test time; no supply-chain risk. |
| 13 | Own small contract-test generator (not Schemathesis). | Simple, fully controlled, good for learning. |
| 14 | Tester writes tests in parallel with Backend and Frontend. | Test-first; saves time; tests aren't biased by the code. |
| 15 | Tester reviews its own failing tests before routing (`tester` owner). | LLM-written tests can be wrong; avoids "fixing" correct code. |
| 16 | UI testing is one code-generated smoke test. | LLM-written browser flows are flaky. |
| 17 | Features carry testable acceptance criteria. | Gives the Tester concrete targets; coverage becomes measurable. |
| 18 | Fix rounds edit existing files (no full regeneration). | Less churn; less risk of breaking what passed. |
| 19 | No approval gates in v1. | Simpler console; pause/stop/messages remain. |
| 20 | Agents built on CrewAI. | User choice; framework learning. Must verify structured output and tools with chosen models. |
| 21 | Models come from OpenRouter; model per agent set in config. | Many models to compare; switching is a config change. |
| 22 | Over budget: stop the run, mark failed `budget`, keep artifacts. | Predictable cost; nothing lost for debugging. |
| 23 | `docs/Essentials/` are short summaries; `architecture.md`, `data-models.md` and this file are the source of truth. | One place to change the design; summaries were drifting (old DB Engineer/Developer agents, Docker image download). |
| 24 | v1 delivers no Docker image download; the ZIP contains a `Dockerfile` and the image is only used for the local preview. | Keeps the ZIP small; anyone can rebuild the image from the `Dockerfile`. |
